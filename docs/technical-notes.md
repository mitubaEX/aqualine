# 実装・データ保持の詳細

## 構成

| 場所 | 役割 |
| --- | --- |
| `src/` | React・TypeScript の日本語 UI |
| `public/` | オリジナルの SVG アイコンなど |
| `server/domain.ts` | 位置判定、投稿制約、表示・保持期間 |
| `server/index.ts` | Worker ルーティング、単一広場の Durable Object、API・WebSocket |
| `wrangler.jsonc` | 本番用の閉じたデフォルトとローカル開発設定 |

単一の SQLite-backed Durable Object（`Plaza`、名前 `aqualine-single-plaza`）が広場の状態・セッション・投稿を管理します。Storage KV API の `plaza`（通常投稿・参加券）、`reports-v1`（通報保存）、`usage-v1`（参加券の操作回数）へ分けて永続化します。SQLite バックエンドであり、別の Workers KV・D1・R2 は使いません。ローカルでは `.wrangler/`、デプロイ後は対象アカウントの DO 名前空間が保存先です。API の各操作と配信時にサーバー側の参加期限を検証します。WebSocket の認証はサブプロトコルを使い、URL のクエリ文字列にトークンを含めません。

## 入場と位置情報

- 道路の近似線に沿う狭い範囲と海ほたる周辺で入場を判定します。東京湾全体を囲む四角形ではありません。
- GPS の精度が足りない、境界付近で判定が曖昧、権限拒否・取得失敗などの場合、新規入場はできません。
- 入場券はサーバー時刻で **最後のエリア内確認から最大60分**。フォアグラウンドで60秒ごとに測位し、確実に範囲内なら更新します。再読み込み・画面復帰・通信復帰は参加券の有効性確認のみで延長しません。
- 判定不能なら期限を延ばさず、既存の期限まで猶予を残します。確実に範囲外ならサーバーが券を取り消します。
- トンネル内では GPS を取得できない場合があります。猶予はトンネルでの利用を保証しません。
- 端末が送る座標は偽装できます。この仕組みは**実在位置の証明ではありません**。開発用バイパスを閉じても、位置偽装は防げません。

参加券と開発モードのフラグだけを同じタブのsessionStorageに保存します。復元時はGET /api/sessionでサーバーが期限・取消しを確認するまで広場を開きません。保存・復元に座標や端末の期限値は使いません。下書き・ミュートなどの画面状態は従来どおりメモリ内のみで、再読み込みでは失われます。

アプリケーションは座標を判定時にのみ使い、座標の履歴を保存したり、明示的にログ出力したりしません。ネットワーク事業者・実行基盤・ブラウザなどのログまで存在しないと保証するものではありません。

## 投稿の制約と保持

- 本文は Unicode コードポイントで 1〜140 文字。URL らしい文字列を拒否しますが、難読化されたリンクまで完全に検出するものではありません。
- 投稿・返信は同一参加券につき **10 秒に 1 件、10 分に 10 件まで**。
- 投稿から **60 分**で通常の取得・表示対象外になります。
- 未通報の投稿は **24 時間**でアプリの保存領域から削除対象になります。
- 通報が保存されると、通報者の参加券では直ちに非表示になります。異なる接続元3つから通報が集まると全体から隔離します。最初の通報から **30 日**保存し、後続通報で期限を延長しません。自分の投稿の削除後も通報保存は期限まで残ります。
- 定期処理による削除には処理間隔分の遅れがありえます。表示対象外になる判定は読み出し時にも行います。

これはアプリの稼働中データに対する方針です。Cloudflare 等のバックアップ、復元履歴、基盤ログの保持条件は未検証であり、物理的な完全消去を約束していません。

## 広く利用を案内する前に必要なこと

現在は小規模な試験公開です。広く一般利用を案内する前に次の整備が必要です。詳しくは [SECURITY.md](../SECURITY.md) を参照してください。

1. 道路・海ほたるの境界を信頼できる地図情報で再作成し、誤入場・誤退出・トンネルの挙動を安全な乗客テストで検証する。
2. 通報の人手確認、異議申し立て、緊急時対応、運営連絡先を用意する。現状は通報による隔離のみで、公開された管理者 API はない。
3. 下記の小規模上限を実際の人数・回線で評価し、大量リクエストへの追加対策と費用監視を整える。
4. プライバシー方針、利用規約、対象年齢、保存・削除とバックアップの取り扱いを確定する。
5. HTTPS、同一オリジン配信、監視・コスト制限、障害時運用を整える。実際の端末・回線で確認する。
6. 公開範囲の拡大や契約変更は別途判断する。現在は依頼に基づく試験公開のみ。


## 小規模運用の上限

`server/limits.ts` に固定した初期値です。上限到達時は 429 または 503 と日本語の理由、Retry-After を返します。上限のために保持期間内の投稿を勝手に捨てません。

| 対象 | 上限 |
| --- | --- |
| 有効な参加券 | 広場全体64枚 |
| WebSocket | 全体64本、参加券ごと2本 |
| 通常投稿・返信 | 128件（24時間保持中の非表示投稿も含む） |
| 通報専用保存 | 別枠128件・96 KiB |
| 通常スナップショットのUTF-8サイズ | 96 KiB |
| 短命の接続元カウンター | 100バケット（世代をまたぐと同一接続元が2個使う場合あり） |
| 同じ接続元からの新規参加 | 10分に60回 |
| 同じ接続元からの投稿・返信 | 10分に120件、参加し直しても共通 |
| 1投稿のリアクション | 全種類合計64個 |

接続元は Cloudflare が付与する CF-Connecting-IP から、ランダムな短命ソルトを使ってハッシュ化します。生IP・座標・識別値はログに出しません。カウンターは最後の対象操作から10分、ソルトは作成から最大30分で削除対象となり、60秒ごとの清掃に従います。ハッシュとソルトは保存するため完全匿名とは言えません。携帯回線や共有Wi-Fiでは別人も同じ制限にかかり、IPを変更した攻撃者は回避できます。

既存スナップショットは読み込み互換を維持します。既に96 KiBを超えるデータは削らず、増加する保存だけを拒否します。保存失敗時はメモリ状態も直前の保存済み状態に戻します。切断後は5〜60秒のバックオフと揺らぎで再接続します。

通常領域と通報領域は別枠です。全体隔離された投稿は通常枠から外れます。1〜2接続元の通報では通常表示も残るので、通常枠にも残ります。通報枠が満杯のときは新しい通報を503で拒否し、保存成功とは表示しません。ミュートは引き続き使え、通常の新規投稿は通報枠満杯の影響を受けません。通報データを勝手に消して空きを作ることはしません。現在の制限はDoS防止や請求額の上限ではありません。15秒ポーリング・60秒アラーム・WebSocket常駐も使用量に影響します。

## Cloudflare の費用とデプロイ準備

**2026-10-29に https://aqualine-mvp.mituba.workers.dev へ試験公開しました。ダッシュボードで実アカウントの Workers Free（$0 / Current plan）を確認済みです。有料契約・プラン変更は行っていません。** [DO公式料金](https://developers.cloudflare.com/durable-objects/platform/pricing/)では SQLite-backed DO は Workers Free でも利用でき、無料枠超過時は操作が失敗します。無料枠は他サービスと共有され、停止や可用性低下はあり得ます。将来有料プランへ変更した場合は超過課金があり得るため、アプリの上限を請求額の上限とは扱わないでください。

このアプリの `observability` は無効、サンプリング0、呼出ログ・ログ保存・トレース保存も無効に設定しています。基盤全体のログ不在を保証するものではありません。[Observability公式料金](https://developers.cloudflare.com/observability/pricing/)は2026年12月1日からの共通料金と、Paidで枠を超えても計測・課金が継続する点を案内しています。アカウントの実プラン、既存サービスの設定、請求は別途確認してください。このプロジェクトから他サービスや契約を変更しません。

更新は `npx wrangler whoami` で対象アカウントを確認してから実行します。秘密値は出力・commitしません。

```bash
npm ci
npm run build
npm test
npx wrangler deploy --env="" --dry-run
npx wrangler deploy --env=""
```

本番は `workers_dev:true`・`ENVIRONMENT:production`。DOバインディングは `PLAZA`、名前空間は `aqualine-mvp_Plaza`（SQLite）、インスタンス名は `aqualine-single-plaza` です。初期化時に未作成の場合だけ空の `plaza` スナップショットを書き、既存データは上書きしません。休止からの起動時は予約済みアラームを維持し、清掃を先送りしません。

`--env local` は本番デプロイに使わないでください。更新後は公開URL、認証なしAPIの401、開発バイパス・範囲外の403を確認します。本番で制限を外した投稿テストはしません。通報の人手運用・連絡先・異議申し立て窓口は未整備で、広く一般利用を案内する段階ではありません。

## 通報票・頻度制限・移行

通報票は参加券数ではなく、投稿ごとにランダムソルトでハッシュ化した接続元で重複排除します。同じIPで参加券を取り直しても全体隔離の票は増えません。各通報者の参加券は本人向け非表示のために記録します。ソルト・接続元ハッシュ・通報者IDは投稿の60分表示終了後の清掃で消し、本文等の通報保存のみ30日残します。生IPや座標は保存しません。

共有バスWi-Fiや携帯NATは複数人でも全体隔離の1票になり、正当な通報が隔離に届きにくい場合があります。それでも本人向け非表示と最初の通報保存は行います。複数回線・IP変更による不当隔離は防げず、3票は本人確認や内容の正しさを保証しません。人手審査は未整備です。

操作制限は参加券単位を中心にしています。UTCの固定1分窓で閲覧30回、更新・削除・リアクション等20回、位置更新6回、WS接続6回。通報は固定10分窓で3回です。境界をまたぐ短時間のバーストはあり得ます。カウンターは別領域に保存して再起動をまたぎ、退出は制限後も可能です。共有回線の60入場・120投稿/10分は緩い補助上限で、IP変更や再入場による濫用を完全に止めません。

DO全体では1分3000リクエスト・処理待ち32件の安全弁を設けています（インメモリなので再起動でリセット）。本文はすべての経路で4 KiB以下、読取全体5秒以内。POST以外の実本文は拒否します。WSは通知受信用で、クライアントのアプリメッセージには応答せず1008で閉じます。プロトコルpingは基盤が処理します。拒否リクエストも基盤使用量になるので、エッジでのDDoS防御や請求上限の代わりにはなりません。

UIは重複送信と同時一覧取得を抑え、一覧の429/503ではRetry-Afterを尊重します。下書きと参加状態を保持し、WSは5〜60秒のバックオフで再接続します。

旧版の隔離済み投稿は、DO起動時のStorageトランザクションで `reports-v1` へ移し、通常枠から除きます。元の通報時刻と内容を保持し、重複移行しません。通常投稿・参加券も保持します。既に上限超過のデータは削らず、容量増加だけ拒否します。通常・通報の変更は同一トランザクションで保存し、失敗時はメモリも保存済み状態へ戻します。更新後に旧版へ単純ロールバックすると通報保存の清掃を扱えないため、障害時は両キーを扱える版で前方修正してください。保存キーを削除する復旧手順は採りません。

## 個人情報を含まない運用集計

同じSQLite DO内の `aqua_daily` テーブルに、UTC日付と `ok`・`denied`・`failed`・`ws_rejected` の件数だけを保存します。本文、URL、IP、座標、参加券、利用者ID、通報者ハッシュは含めません。当日を含む7日分で、60秒の清掃周期に従います。本文ログ・トレースは引き続き無効です。

既存のCloudflare管理画面 → Durable Objects → Plaza → Data Studio → `aqualine-single-plaza` で、次の読取SQLを使えます。公開の監視APIは設けません。

```sql
SELECT day, ok, denied, failed, ws_rejected FROM aqua_daily ORDER BY day DESC;
```

`failed` はアプリの503等を含み、基盤の未捕捉例外数とは別です。書込障害時は集計を欠落させても保存済み操作の結果を変えません。全体3000回/分の安全弁を超えた拒否は最初の1件のみ数えます。Worker側のOrigin拒否やアセット配信はこのDO集計に含みません。正確な課金計測にはCloudflareの使用量画面も確認してください。集計のためのSQL書込にも無料枠の使用量が発生します。

WebSocket hibernation は[公式推奨](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)ですが、今回は採用していません。現在の参加期限に合わせた接続タイマーを、復帰時の認証再構成・アラーム駆動へ変える必要があります。期限切れ即時切断の挙動を維持するため、この変更とは分けて検証する課題として残します。新規サービス、D1、権限拡大、有料プラン、MFA変更は不要で、実施していません。

## トンネル・渋滞時の参加継続（2026-10-31）

- 有効期限はサーバーの入場／最後にエリア内と判断した測位から60分。測位が不確定・取得失敗・通信断・再読み込みでも延長しない。精度条件を満たした範囲外判定は即時取消し・WS切断。期限後の更新も認証で拒否する。
- 保存済みの旧20分券は、そのexpiresAtのまま。移行や復元で60分へ書き換えず、期限切れ券は復活しない。旧券でも期限内に新しくエリア内確認できれば60分へ更新する。
- 読取専用GET /api/sessionは通常の参加券認証・閲覧回数制限・no-storeを適用。serverNowとexpiresAtを返すだけで、入場券の期限を書き換えない。通信・画面復帰と復元はこのAPIを使用する。
- 表示時計はサーバー応答時刻＋performance.nowの経過時間を使用。端末のDate.now変更は猶予を伸ばさない。休止中のブラウザ時計の挙動はOS依存だが、復帰時にサーバー確認し、すべてのAPI/WSで期限を再判定する。時計表示はアクセス権限ではない。
- sessionStorageの形式不正・無効券・期限切れは破棄。通信エラーは保存券を残して再試行可能とするが、確認前には広場や投稿を表示しない。復元確認は15秒でタイムアウト。保存が禁止されたブラウザでは現在の参加は使えるが再読み込み復元はできない。
- sessionStorageはタブ単位で、XSSや端末利用者から秘密を守る保管庫ではない。ブラウザによるタブ複製・復元時のコピーもあり得る。既存の参加券別接続数・操作回数制限は維持する。退出・失効時は保存券を消す。
- 猶予中はアクアラインを離れていても位置が判明しなければ最大60分残れる。GPS未取得での新規入場は許可せず、IPや模擬位置を所在地の証拠にしない。トンネル側の未補正近似は残る。電波が届かない間は通信できず、オフライン投稿キューは追加していない。
- 60分化により同時参加・接続の占有時間が長くなり、既存の容量上限に達しやすくなる。無料枠・大量同時利用を保証しない。実機トンネル測位・通信は未検証。操作は同乗者が安全に行える時のみ。
