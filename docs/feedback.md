# フィードバック運用

## 利用者向け

入口・広場の画面下部に「ご意見・不具合を送る」を配置。位置情報、参加券、連絡先は不要です。種類（不具合／アイデア・要望／その他）と本文（Unicodeコードポイント1〜500文字）のみを送信し、広場には公開しません。個人情報・緊急連絡は禁止、返信は約束しません。

送信失敗・タイムアウトでは本文を保持し、同じ内容の再試行は同じUUIDで重複を防ぎます。本文や種類を変更した場合は新しい送信です。再読み込みやタブを閉じると下書き・再試行キーは失われます。

## 公開前の必須設定

この変更はシークレットを作成・設定せず、公開もしません。運営者の許可を得たうえで `FEEDBACK_ADMIN_TOKEN` をWorkerシークレットに設定してください。32文字以上の十分にランダムな値を安全なシークレット管理経路で設定し、チャット・コード・URL・Vite変数に貼らないでください。未設定・短い設定では管理APIは401で閉じます。未設定の場合は受付も503で停止し、確認できないご意見を蓄積しません。公開前に受信箱のアクセス確認が必須です。

ローカル検証は `.dev.vars` の専用ダミー値を使い、本番の秘密は流用しないでください。リポジトリにコミットしないでください。

## 運営の確認

アプリの `/feedback-admin` を直接開くと運営用画面が表示されます。管理用キーをパスワード欄に入力し「受信箱を開く」。未確認件数・種類・本文・時刻を読み、個別に確認済みにできます。キーはReactメモリのみで保持し、URL・localStorage・sessionStorageに保存せず、送信はAuthorizationヘッダーのみです。「閉じて消去」でキーと表示内容を消去。画面自体のURLは秘密ではなく、データ取得は必ずサーバー認証します。ブラウザ拡張・パスワードマネージャー等による保存までは制御できません。

管理クライアントからHTTPSで `Authorization: Bearer <secret>` を付けて `GET /api/admin/feedback`。JSONの `unread` が未確認件数、`feedback` が新しい順の一覧です。項目は id, category, text, createdAt, reviewedAt。再試行キーや接続元ハッシュは公開しません。本文は信頼しない利用者入力です。HTMLとして実行せず、テキストとして表示してください。

確認後は同じ認証で `POST /api/admin/feedback/{id}/reviewed` に空JSON `{}` を送ります。繰り返し実行しても最初の確認時刻を保ちます。削除APIはありません。既読化は保持期限を延ばしません。

自動通知やメール転送は未設定です。受信箱を運営者が定期的に確認する運用が必要です。通知先・頻度が決まったら別途設定してください。

## 保存・上限

- 専用 `feedback-v1` 領域で30日保存、毎分のアラームで期限切れを清掃。読み出し時にも期限切れを除外。
- 40件または96 KiBまで。満杯なら503で受付失敗を明示し、既存の未確認・確認済み内容を勝手に押し出しません。通常投稿枠とは別です。
- 接続元ごと10分に3件。生IPは保存せず、短命なソルト付きハッシュを使用。共有回線では別人も同じ上限になり、回線を変えた濫用は防ぎきれません。
- 同一オリジン制約、4096バイト本文制限、5秒読取期限、既存の全体・同時要求上限を適用。
- 保存の成功後だけ受付IDを返します。失敗時はトランザクションで戻します。基盤のバックアップ・ログの保持は別です。

## メッセージ1日化の移行

通常投稿はサーバー／画面共通の24時間で表示終了・削除対象。参加券の60分は変更なし。追加の一括削除や移行は実行しません。以前60分で非表示になっていた未削除の投稿は、公開時に24時間未満なら再び見える可能性があります。通報内容30日保持は維持し、通報の短命識別子は新しい表示終了（24時間）で清掃します。将来の公開判断時にこの保持差分を確認してください。
