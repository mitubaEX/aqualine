# AquaLine

**同じ道の、いまを話そう。**

アクアラインを通るバスなどの**乗客**向け、一時的な広場のローカル MVP です。東京方面・木更津方面のタグを付けながら、同じ広場で短い会話ができます。運転者は利用しないでください。渋滞中・停車中も運転操作が必要な方は対象外です。

> 実装・検証用です。公開サービスではありません。外部へのデプロイ、クラウドアカウントや認証情報の作成はしていません。位置判定の境界は近似値で、公開前の実地検証が必要です。

## できること

- 乗客であることの確認、進行方向の選択、位置確認による入場
- 乗車ごとの匿名表示名。名前・メールアドレスなどの登録なし
- 140 文字までの投稿・返信と、3 種類のリアクション
- 自分の投稿削除、相手のミュート、投稿の通報
- WebSocket による更新通知と、通信状態の表示
- 位置が不明なときの猶予、エリア外での退出、参加期限切れの処理
- 開発時だけの、実際の位置情報を使わないテスト入場

写真、DM、フォロー、ランキング、架空ユーザーや自動生成の会話はありません。ブルーのアイコンは吹き出し・橋・波を組み合わせたオリジナルです。

## ローカル起動

Node.js 24 系と npm を推奨します。まず依存関係をインストールします。

```bash
npm ci
npm run build
npm run dev
```

ブラウザで **http://127.0.0.1:5173** を開きます。画面は Vite、API はローカルの Wrangler / Durable Objects エミュレーター（127.0.0.1:8787）で動きます。Cloudflare へのログインやデプロイは不要です。初回ビルドは Wrangler が参照する `dist/` を作るために必要です。

最初は**開発用テスト入場**を使ってください。これは実際の現在地を取得しません。実際の位置を使う入場とは明確に分かれています。本番用ビルドでは開発用入場ボタンを表示せず、API も `ENVIRONMENT=development` かつ localhost のときにだけ開発指定を受け入れます。

複数人の動作を確認するには、別のブラウザコンテキスト／シークレットウィンドウで開き、それぞれ入場します。空の広場から始まるため、投稿は自分で作成してください。開発中の投稿も実際にローカルの保存領域に書き込まれます。

### 検証コマンド

```bash
npm run typecheck
npm test
npm run build
npm run test:e2e
```

E2E のブラウザ設定と実行条件は `playwright.config.ts` を参照してください。この作業環境には `/usr/bin/chromium` があります。別環境では Playwright のブラウザ設定を合わせる必要があります。コマンドの存在と、その環境で実行済みであることは別です。検証結果は納品時の実行報告を参照してください。

## 構成

| 場所 | 役割 |
| --- | --- |
| `src/` | React・TypeScript の日本語 UI |
| `public/` | オリジナルの SVG アイコンなど |
| `server/domain.ts` | 位置判定、投稿制約、表示・保持期間 |
| `server/index.ts` | Worker ルーティング、単一広場の Durable Object、API・WebSocket |
| `wrangler.jsonc` | 本番用の閉じたデフォルトとローカル開発設定 |

単一の Durable Object が広場の状態・セッション・投稿を管理します。API の各操作と配信時にサーバー側の参加期限を検証します。WebSocket の認証はサブプロトコルを使い、URL のクエリ文字列にトークンを含めません。

## 入場と位置情報

- 道路の近似線に沿う狭い範囲と海ほたる周辺で入場を判定します。東京湾全体を囲む四角形ではありません。
- GPS の精度が足りない、境界付近で判定が曖昧、権限拒否・取得失敗などの場合、新規入場はできません。
- 入場券はサーバー時刻で **20 分**。フォアグラウンドで 60 秒ごと、および画面へ戻った際に再確認し、確実に範囲内なら更新します。
- 判定不能なら期限を延ばさず、既存の期限まで猶予を残します。確実に範囲外ならサーバーが券を取り消します。
- トンネル内では GPS を取得できない場合があります。猶予はトンネルでの利用を保証しません。
- 端末が送る座標は偽装できます。この仕組みは**実在位置の証明ではありません**。開発用バイパスを閉じても、位置偽装は防げません。

参加券・セッション・乗客確認・ミュートの画面状態はメモリ内のみです。再読み込みすると画面上の参加状態とミュートは失われます（元のサーバー側参加券は期限まで残ります）。

アプリケーションは座標を判定時にのみ使い、座標の履歴を保存したり、明示的にログ出力したりしません。ネットワーク事業者・実行基盤・ブラウザなどのログまで存在しないと保証するものではありません。

## 投稿の制約と保持

- 本文は Unicode コードポイントで 1〜140 文字。URL らしい文字列を拒否しますが、難読化されたリンクまで完全に検出するものではありません。
- 投稿・返信は同一参加券につき **10 秒に 1 件、10 分に 10 件まで**。
- 投稿から **60 分**で通常の取得・表示対象外になります。
- 未通報の投稿は **24 時間**でアプリの保存領域から削除対象になります。
- 通報された投稿は直ちに通常の一覧から隔離され、通報から **30 日**で削除対象になります。
- 定期処理による削除には処理間隔分の遅れがありえます。表示対象外になる判定は読み出し時にも行います。

これはアプリの稼働中データに対する方針です。Cloudflare 等のバックアップ、復元履歴、基盤ログの保持条件は未検証であり、物理的な完全消去を約束していません。

### ブラウザ検証の制約
この実行環境では Chromium がプロセス用ソケットを作成できず、ブラウザはページ表示前に起動失敗しました。代替 headless-shell も配布ファイルを正常取得できませんでした。従って **4 件の自動ブラウザ E2E は未実行**です。別のサポートされたクラウドブラウザ経由では、デスクトップの実描画を確認し、乗客確認→合成位置で参加→投稿→リアクション→返信→確認ダイアログで自己削除→退出を手動検証しました。残り時間の初期表示と画面スクロールの不具合を修正し、再ビルド済みです。モバイル表示、権限拒否・オフライン等の全ブラウザシナリオは未確認です。ブラウザスクリーンショットは成果物に保存していません。上記の HTTP / WebSocket 結合テスト成功とは区別してください。利用可能なローカル Chromium で `CHROMIUM_PATH=/path/to/chromium npm run test:e2e` を実行できます。

このクラウド検証環境ではネットワークインターフェースの列挙も未対応のため、テスト時だけループバックのみ返す補助設定で Wrangler を起動しました。アプリ本体や本番設定にはその補助設定を含めていません。
